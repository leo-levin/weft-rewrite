# WEFT IR Design

## Context

The WEFT compiler lowers an AST into an intermediate representation that feeds a shared expression traversal with per-backend leaf translators. This spec settles the IR's node types, how it's constructed, and the boundary with name resolution.

Goals for the IR:

- Small enough to hold in the head at once.
- Clear — each node has one well-defined meaning.
- Cheap to build (single pass) and traverse (SSA-style).
- Native support for an explicit feedback-buffer model; no fixed-point machinery.

Supersedes the sketch in `docs/compiler-notes-apr-8.md` (which had 12 nodes, width annotations per node, and distinct `signal`/`call` nodes).

## Core insights

### 1. Hash-consing makes the IR a DAG

Every IR node is interned: before allocating, the constructor looks up a memo table keyed by the node's content (operator tag + child IDs). Identical subtrees collapse to a single ID.

Consequences:
- Structural equality is pointer equality (`id1 == id2` ⟺ subtrees equal).
- Common subexpressions share automatically across the whole program. No separate CSE pass.
- Inlining duplicates at the *source* level but shares at the *IR* level. `f(x) = x*x + x` called as `f(noisy)` expands to three references that all hash-cons to the same `noisy` ID.

### 2. `where` is substitution

`body where { x = e }` means "replace free occurrences of `x` in `body` with `e`." Bindings are ordered (earlier names visible to later bindings and to the body). Forward references and mutual recursion between bindings are errors — both at `where`-scope and at top level.

Under this semantics, `where` does not introduce a new semantic concept; it's syntactic sugar for substitution.

### 3. Only functions take args. Signals are referenced by name. Coord remaps are `where`-on-coord.

Two kinds of top-level definitions:

- **Functions** — declared with params: `f(x, y) = body`. Called as `f(a, b)`. Arguments bind to params positionally.
- **Signals** — zero params: `g = body`. Referenced by name alone: `g`.

There is no `foo(args)` syntax for zero-param signals. To sample a signal at a shifted coordinate, use `where` with the coord on the left-hand side:

```
foo2 = foo where { @t = @t - 3 }        -- foo sampled 3 seconds in the past
shifted_img = img where { @x = @x + 1 } -- img translated right
```

`where { @t = @t - 3 }` binds the *coord sigil* `@t` (not a name) to the expression `@t - 3`. During substitution, every occurrence of `@t` in the body is replaced by `@t - 3`. This subsumes the remap operator (formerly `~`); there is no separate remap construct.

`where` bindings can therefore have two kinds of LHS: a regular name (or destructuring tuple of names), or a coord sigil. Both extend the substitution env the same way — the only difference is what they bind.

This requires a grammar extension: `Binding`'s simple case must accept `coord = Expr` alongside `name = Expr`. (See the Grammar note below.)

The IR has **no `call` or `signal` node**. Function application desugars to `where`-with-name-bindings at IR construction; signal remap is `where`-with-coord-bindings.

### 4. The default for every reference is inlining. Self-reference is the only case that can't inline, and becomes a buffer read.

Inlining a non-recursive def always terminates: the body is built under an extended env, hash-consing dedupes, done. This holds whether or not the reference is wrapped in coord-remap `where`s — `foo where { @t = @t - 3 }` with `foo = sin(@t)` inlines to `sin(@t - 3)`. No history is required; the body is a pure function of runtime coordinates and can be recomputed at any coord.

**Self-reference is the sole exception.** Consider a frame-blended accumulator:

```
trail = (trail where { @t = @t - 1/60 }) * 0.9 + camera
```

Inlining `trail` into its own body would unfold forever under substitution. The runtime breaks the cycle by allocating a buffer: during resolution, `trail` gets a pre-allocated `BufferID`, and every reference to `trail` — including the one inside its own body — becomes `buffer(trailID, [@t, @x, @y])`. The surrounding `where { @t = @t - 1/60 }` substitutes `@t` inside those index expressions, yielding `buffer(trailID, [@t - 1/60, @x, @y])` — a read of the previous frame.

The body itself is compiled as a separate rooted expression ("what gets written into `trailID` this frame"), which is that same expression but with its *own* references to `trail` resolved to the buffer read.

Buffer shape is inferred from the time-offset of the self-reference: `1/60` → frame-rate texture, `1/@sr` → sample-rate delay line, else compile error (rate must be statically recognizable).

Because mutual recursion is banned (both at top level and inside `where`-scopes), cycle detection reduces to a single-node check: does `f`'s body mention `f` transitively? If yes, allocate a buffer.

Other kinds of "stateful-looking" references — hardware inputs (camera, mic), `#curve`, cross-domain signals — become `buffer` leaves too, but not for the same reason. The runtime declares them as buffers at allocation time; the compiler just sees opaque `buffer` leaves. Those are runtime decisions, not an outcome of the recursion analysis.

## IR nodes

```swift
typealias ID = Int   // index into nodes array

enum IRNode {
    case num(Float)
    case coord(CoordKind)
    case buffer(BufferID, indices: [ID])
    case tuple([ID])
    case index(ID, Int)
    case binOp(BinOp, ID, ID)
    case unOp(UnOp, ID)
    case ifExpr(cond: ID, then: ID, else_: ID)
    case reduce(ReduceOp, body: ID, bounds: [(Int, Range)])   // Int = De Bruijn depth
    case whereBind(lhs: BindLHS, bound: ID, body: ID)         // debug wrapper
}

enum BindLHS: Hashable {
    case name(String)
    case coord(CoordKind)
}
```

**10 cases.** The enum is *not* `indirect`: children are `ID`s (integers), not nested nodes. Nodes live in a flat array; no boxing, no cycles-by-reference.

| Node | Role | Notes |
|------|------|-------|
| `num` | Numeric literal | Canonicalize `-0.0 → 0.0`, one `NaN`. |
| `coord` | Runtime scalar leaf | `@x @y @t @i @sr @w @h #param`. |
| `buffer` | Indexed runtime buffer leaf | Camera, mic, `#curve`, feedback, cross-domain, textures. |
| `tuple` | Structural aggregation | Width = count of children. |
| `index` | Tuple component selection | `expr.0`, `expr.-1`, etc. |
| `binOp` | Binary arithmetic/comparison/logical | Single enum; operator inside. |
| `unOp` | Unary negation/not | Could desugar (`-x` = `binOp(-, 0, x)`). Kept for clarity — remove if it carries no weight. |
| `ifExpr` | Branch | Both branches must match in width. |
| `reduce` | Aggregate over coordinate range leaf | Bound variables addressed by De Bruijn depth. |
| `whereBind` | Debug wrapper preserving a source binding | LHS is name or coord. Semantically inert; backend codegen can pass through. |

### CoordKind

```swift
enum CoordKind {
    case x, y, t, i, sr, w, h
    case param(String)          // #param name
}
```

### BufferID

```swift
struct BufferID: Hashable {
    let index: Int              // opaque; runtime resolves to actual storage
}
```

Allocation is runtime's job: one per hardware input, one per `#curve`, one per recursive def, one per cross-domain boundary.

### BinOp / UnOp / ReduceOp

```swift
enum BinOp { case add, sub, mul, div, mod, pow, eq, ne, lt, le, gt, ge, and, or }
enum UnOp  { case neg, not }
enum ReduceOp { case sum, product, min, max, any, all }
```

## Program structure

```swift
struct Program {
    var nodes: [IRNode]                      // hash-consed, ID-indexed
    var sinks: [(SinkKind, ID)]              // outputs (display, play, dmx, ...)
    var feedbackBodies: [(BufferID, ID)]     // recursive-def writer expressions
    var widths: [Int]                        // widths[id] = output width of nodes[id]
}

enum SinkKind { case display, play, dmx, osc }
```

`sink` is **not** an IR node — it's a program root. The IR is evaluated *toward* sinks; nothing inside the expression tree writes a sink.

## Construction algorithm

The constructor maintains:

```swift
var nodes: [IRNode] = []
var memo: [NodeKey: ID] = [:]
var nameEnv: [String: ID] = [:]       // name bindings from `where { name = ... }` and function-call params
var coordEnv: [CoordKind: ID] = [:]   // coord remaps from `where { @t = ... }`
```

Core primitive:

```swift
func mk(_ node: IRNode) -> ID {
    let key = NodeKey(node)
    if let existing = memo[key] { return existing }
    let id = nodes.count
    nodes.append(node)
    memo[key] = id
    return id
}
```

Walking the AST bottom-up:

| AST node | Action |
|----------|--------|
| `num(n)` | `mk(.num(n))` |
| `coord(k)` | If `k` is rebound in `coordEnv`, return `coordEnv[k]`. Otherwise `mk(.coord(k))`. |
| `name(s)` | First check `nameEnv[s]` (local where-binding or function param). If absent, resolve against `Resolved.defs[s]`: non-recursive signal → walk its body in the *current* env (picks up coord remaps at the reference site); recursive signal → `mk(.buffer(bufferID, currentCoordIndices))` where `currentCoordIndices[i] = coord(freeCoord[i])` looked up through `coordEnv`. Bare reference to a function (no args) is a compile error. |
| `tuple(es)` | Build each; `mk(.tuple(ids))` |
| `index(e, i)` | If `e`'s ID is a `.tuple`, return the i-th child ID directly (peephole). Otherwise `mk(.index(eID, i))`. |
| `binOp(op, a, b)` | `mk(.binOp(op, aID, bID))` |
| `unOp(op, e)` | `mk(.unOp(op, eID))` |
| `ifExpr(c, t, f)` | If `c` is a known-constant `num`, return `t` or `f` directly. Otherwise `mk(.ifExpr(...))`. |
| `call(fname, args)` | Resolve `fname` to a function in `Resolved.defs` (must have non-empty params; must be non-recursive — recursive functions are a compile error). Build each `arg → argID` in current env. Extend `nameEnv` with `params → argIDs`. Walk `body` → `bodyID`. Pop extensions. Return `bodyID`. |
| `whereExpr(body, bindings)` | Walk bindings in order. For each, build `expr → exprID` in the current env, then extend the appropriate env: `name = expr` → extend `nameEnv`; `(a,b,...) = expr` → extend `nameEnv` for each name with peephole-indexed tuple access; `@k = expr` → extend `coordEnv[k]`. Build `body` in the fully extended env → `bodyID`. Pop extensions. Wrap with nested `whereBind` nodes (outermost binding last). |

Notes:

- `whereBind` is inert at the semantics level. The body's ID was built with bound names/coords already resolved via the envs; wrapping doesn't change what's computed. It exists so pretty-printers can show source-level structure.
- Because `whereBind` is in the hash-cons key, two `where` wrappers with different LHS around the same body produce distinct nodes — intentional.
- `call` never survives into the IR: it fully inlines via env extension. Hash-consing handles any resulting duplication.
- Coord remaps of signals are uniform: `g where { @t = e }` works identically whether `g` is non-recursive (substitution reaches the raw `coord` leaves in `g`'s inlined body and swaps them for `e`) or recursive (substitution reaches the `@t` index inside `buffer(gID, ...)` and swaps it for `e`).
- Peephole reductions (`index` into literal tuple; `ifExpr` with constant condition) happen at construction time.

## Resolution pass

Runs before IR construction. Input: the AST. Output:

```swift
struct Resolved {
    var defs: [String: ResolvedDef]
}

enum ResolvedDef {
    case nonRecursive(params: [String], freeCoords: [CoordKind], body: AST.Expr)
    case recursive(bufferID: BufferID,
                   params: [String], freeCoords: [CoordKind],
                   body: AST.Expr, offsetKind: OffsetKind)
}

enum OffsetKind { case frameRate, sampleRate }
```

Responsibilities, per top-level def:

1. **Collect referenced names and coords.** Walk the body, record every `name` and `coord` reference.
2. **Compute the free coord set.** The `@`-coords the body reads transitively (including through non-recursive calls and signal references, minus any coords rebound by intervening `where`s). Used for partitioning decisions — *not* for positional arg binding, since signals don't take args.
3. **Detect self-reference.** Does `f`'s body mention `f`? (Mutual recursion is banned; only direct self-reference exists.)
4. **Infer self-reference offset rate.** For each self-referential signal, find the coord-rebind applied in the self-reference. Classify the time offset as `frameRate`, `sampleRate`, or error. Allocate a `BufferID`. Record the buffer's coord dimensions (the def's free coord set).
5. **Validate function-call arity.** For every `call(fname, args)` site, `args.count` must equal the function's param count.
6. **Ban recursive functions.** A function (def with params) whose body calls itself is a compile error — there's no natural buffer shape for function recursion.
7. **Report errors.** Forward references, mutual recursion, recursive self-ref with non-static or mismatched-rate offset, function-arity mismatches, recursive functions, `@coord = expr` where `@coord` isn't in the relevant scope's receiving coord set.

Top-level defs are ordered (per grammar). A def can only reference previously-declared defs, which makes resolution a single forward scan.

## Width inference

Widths live in a side-table, populated in one pass after construction:

```swift
func computeWidths(program: inout Program) {
    for id in 0..<program.nodes.count {
        program.widths.append(widthOf(program.nodes[id], program.widths))
    }
}
```

Per-node rules:

- `num` → 1
- `coord` → 1
- `buffer(id, _)` → declared width at allocation time (camera = 3, mic = 1, `#curve` = 1, feedback = width of def body)
- `tuple(children)` → `children.count`
- `index(_, _)` → 1
- `binOp(_, a, b)` → widths must match, or one must be 1 (broadcast). Result = max.
- `unOp(_, a)` → width of `a`
- `ifExpr(_, t, f)` → widths of `t` and `f` must match. Result = that width.
- `reduce(...)` → 1
- `whereBind(_, _, body)` → width of `body`

Because IDs are assigned in construction order (children always have smaller IDs than parents), the sweep is a simple `for id in 0..<nodes.count`. O(n).

Width mismatches become errors reported with the source location of the offending AST node (provenance table mapping ID → source span is maintained alongside `nodes`).

## Open questions / deferred

- **Reduce-bound variables: De Bruijn depth vs. fresh strings.** Current spec uses De Bruijn depth so that α-equivalent reductions (`sum(x+1 for x in 0..1)` and `sum(y+1 for y in 0..1)`) hash-cons to the same node. This is the compiler-literature default and adds negligible weight. Alternative — keep names, accept that reduce bodies don't share across different variable names — would simplify slightly at the cost of missed CSE. Staying with De Bruijn.

- **`unOp` — keep or desugar?** `-x` ≡ `binOp(sub, num(0), x)`, `!x` ≡ `binOp(eq, x, num(0))`. Keeping `unOp` costs one enum case; desugaring loses a bit of IR legibility. Minor. Keep for now; remove if it never earns its weight.

- **Provenance table.** Each IR node should have at least one associated source span for error reporting. A `[ID: SourceRange]` side-table works. Needs to handle one-node-to-many-sources (hash-consing merges distinct source locations into one node). Defer detailed design.

- **Grammar extension for coord-LHS bindings.** `where { @t = @t - 3 }` requires the `Binding` rule to accept a coord sigil on the left. Current grammar:
  ```
  Binding = "(" NonemptyListOf<name, ","> ")" "=" Expr  -- destructure
          | name "=" Expr                                -- simple
  ```
  Needed revision (one of):
  ```
  Binding = "(" NonemptyListOf<name, ","> ")" "=" Expr  -- destructure
          | (name | coord) "=" Expr                      -- simple
  ```
  This is a trivial grammar edit but needs to happen before resolution can accept the new syntax.

- **`String` literals.** AST has `string`; IR does not. String values aren't runtime quantities in WEFT — they're config/parse-time only. If a string survives into IR construction, that's a compile error.

## Not in scope

- Resolution implementation (its own spec).
- Backend leaf translators (Metal, CoreAudio, DMX, OSC — one spec each, probably).
- Runtime buffer allocation and scheduling.
- **Partitioning.** Sketched at a high level (free coord set → inherent domain; cross-domain boundaries become buffers) but the pass itself, cross-domain buffer allocation, and edge cases (mixed-domain branches, polymorphic pure defs) are deferred to a separate spec.

## Touches adjacent code, but minimal

- **Grammar + AST:** one new binding form (`coord = Expr` alongside `name = Expr`). Parser and `AST.Binding` gain one case.

## Summary

| Concern | Prior sketch | This spec |
|---------|--------------|-----------|
| Node count | 12 (+ `signal`, `call`, `sink`) | 10 |
| Width storage | Annotation on every node | Side-table, one O(n) sweep |
| Call/signal | Distinct nodes | β-reduced at construction, absent from IR |
| CSE | Deferred pass | Free via hash-consing |
| Self-reference | Detected, special-cased mid-pipeline | Pre-resolved in name resolution; leaf in IR |
| Signal remap | Separate `~` operator / distinct node | `where { @coord = expr }` — unified with name-binding `where` |
| `where` | Flattened to named defs at lowering | Inert `whereBind` wrapper; body already substituted |
| DAG construction | Not specified | Hash-consed bottom-up walk |
